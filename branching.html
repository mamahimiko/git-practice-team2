Why Branching is important?

Branching in Git lets developers work independently without affecting the main project.
By creating a branch, you can safely add features, fix bugs, or test ideas without breaking
the main code. Once your changes are tested, you merge the branch back to keep the project
stable and updated.

It is important because

  • Keeps the main code safe – You can try new things without breaking the main project.
  • Helps group work – Many developers can work on different parts at the same time.
  • Helps with testing – You can check each branch before adding it to the main code.
  • Easy to combine – When the work is ready, you can merge it back into the main branch.

Make a new branch

step1 : Create and Switch to a New Branch

git checkout -b branch_name

This command makes a new branch and switches to it right away.
Each branch is like a separate workspace where you can work freely.

step2: Add your changes

git add .

This gets your changed files ready to be saved (committed).
It means “I want Git to track these changes.”

step3: Save your changes (commit)

git commit -m "message"

This saves your work in the branch.
The message should describe what you did, so others can understand your changes easily.

step4: Push the branch to GitHub

git push origin branch_name

This sends your branch and all your changes to GitHub.

step5: Merge the branch into main

git checkout main git merge branch_name

Now you switch back to the main branch and combine (merge) your changes into it.
After merging, the main branch will include your updates.

step6: Delete the Branch (Local)

git branch -d branch_name

If your branch is already merged, you can delete it safely.
This helps keep your workspace clean.

step7: Delete the Branc_h on GitHub

git push origin --delate name

If you also want to remove the branch from GitHub, use this command.
Only delete branches that you no longer need.
